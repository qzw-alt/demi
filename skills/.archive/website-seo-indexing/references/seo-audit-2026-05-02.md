## Initial Audit Findings (misleading — audit script had bugs)

PowerShell audit script had two bugs:
1. `has_canonical` regex matched content INSIDE other tags (e.g. `content="...canonical..."` in image URLs)
2. `has_og_site_name` regex didn't match because PowerShell's `-match` is case-insensitive but the field name was actually present

## Real Problems Found

1. **Duplicate canonical/og:url** — 59 files had 2x canonical and 2x og:url (Phase 2 injection script re-added instead of checking)
2. **Wrong canonical URL** — `hair-transplant-china-2026.html` canonical pointed to `https://chinahospitalsguide.com/hair-transplant-china-2026.html` (root, not /blog/)
3. **Duplicate twitter:card** — 4 files had 2x twitter:card

## Lessons Learned

- Always verify audit script output against a sample of actual files before trusting totals
- Check for duplicate tags specifically — batch injection scripts often re-add instead of update
- PowerShell regex behaves differently from Python/re (case sensitivity, multiline flags)
