# Two-Track Publishing Architecture — chinahospitalsguide.com

**Verified 2026-07-11.** This is the single most-asked question by future cron agents: "the guide says blog/*.md, the cron says news/*.html, which is it?"

## The answer

**Both. They are parallel tracks.**

| Track | Path | Format | Trigger |
|---|---|---|---|
| Daily news | `news/YYYY-MM-DD-<slug>.html` | Self-contained HTML, inline `<style>`, JSON-LD `Article` only | **Daily cron prompt** — this skill |
| Pillar pieces | `blog/<slug>.md` | Markdown + Nunjucks frontmatter, `layout: blog-post.njk`, JSON-LD `Article + FAQPage` array | CONTENT_GUIDE.md — SEO/UX team |

The 2026-07-10 Eleventy migration converted the existing `blog/*.html` pillar pages to `.md` with frontmatter. The `news/` daily-cron path did NOT change.

## What the daily cron cares about from CONTENT_GUIDE.md

- **Pricing benchmark table (§5)** — share the CAR-T, CABG, knee replacement, IVF, etc. price ranges. Both tracks cite these. Daily news articles quote the table verbatim with a "2026 estimates" tag.
- **Patient-source prioritization (§2)** — the real patient flow (东南亚 22% / 俄罗斯中亚 / 中东 / 非洲 / 美欧) shapes daily news framing (e.g. write "Why Indonesian and Vietnamese cancer patients choose China" rather than "American patient saves 80%").
- **Internal-link targets** — `/blog/<pillar>.md` URLs after the migration have pretty-URL form `/blog/<slug>/` (per `references/chinahospitalsguide-content-guide.md` pitfall #2). Daily news internal links should use the pretty form for SEO consistency.

## What the daily cron does NOT inherit from CONTENT_GUIDE.md

- **Frontmatter `layout: blog-post.njk`** — applies only to `blog/*.md`.
- **JSON-LD as array `[Article, FAQPage]`** — applies only to `blog/*.md`. Daily news uses a single `Article` schema object.
- **FAQ section with FAQPage schema** — pillar-piece requirement. Daily news can have an FAQ section but does not need to ship the structured-data array.
- **`npx @11ty/eleventy` build step** — pillar pieces only. Daily news ships as static HTML in `news/`.

## Decision flowchart

```
Article is on a topical news event (NMPA approval, NEJM publication, EHA/ASCO readout)?
  → Daily news track → news/YYYY-MM-DD-slug.html
  → Self-contained HTML, inline CSS, single Article JSON-LD
  → Sitemap entry at repo root sitemap.xml
  → Verify: curl https://chinahospitalsguide.com/news/YYYY-MM-DD-slug.html

Article is an evergreen reference (cost guide, hospital directory, procedure deep-dive)?
  → Pillar piece track → blog/slug.md
  → Nunjucks frontmatter, blog-post.njk layout, Article+FAQPage JSON-LD array
  → Eleventy builds to _site/blog/slug/index.html
  → Sitemap auto-generated by Eleventy post-build scripts
  → Verify: curl https://chinahospitalsguide.com/blog/slug/
```

## Why two tracks (don't try to merge them)

- Daily news is **topical + perishable**: written in response to current events, 1,200-1,800 words, ships within 48-72h of the news event, FAQPage schema is overkill for that shape.
- Pillar pieces are **evergreen + compounding**: 4,000-8,000 words, written for multi-year SEO value, FAQPage schema drives featured snippets, frontmatter tooling enables structured updates and SEO metadata (kicker, subtitle, pageStyle).
- Forcing one format on both either bloats daily news with frontmatter tooling it doesn't need or strips pillar pieces of FAQPage structured data.
- The two tracks can cross-link freely: a daily news article can link to a pillar piece, and a pillar piece can reference a recent daily news article as "Latest news" in its footer.

## Common confusion modes (avoid these)

1. **"The CONTENT_GUIDE says blog/.md, so I should write there."** No — you're running the daily cron. Use `news/`.
2. **"The CONTENT_GUIDE says use Article+FAQPage array, so I should ship that schema."** No — daily news uses single Article schema. FAQPage is for pillar pieces.
3. **"I should run `npx @11ty/eleventy` after writing the article."** No — `news/` is served as static HTML. The build step is for `blog/`.
4. **"My internal link to /blog/car-t-therapy-china-2026.html should use the .html form."** No — after the migration, pillar pieces are at `/blog/car-t-therapy-china-2026/` (pretty URL). Use the trailing-slash form for new internal links (verified in `references/chinahospitalsguide-content-guide.md` pitfall #2).
5. **"I need to update sitemap.xml manually for the daily news article."** Yes — daily news does require manual sitemap.xml patch at repo root (the SEO batch touch is for pillar pieces). The `references/site-configs.md` "chinahospitalsguide.com" section has the exact entry format.
