## 2026-07-25 · 邮件 / 微信起稿的"复制用"强偏好（多次反馈）

**用户触发原文**（同一会话内 5+ 次重复触发同一偏好）：
> - "**不用写那么长**"
> - "**直接发我**"
> - "**改好 发我**"
> - "**你用了以下内容然后一段发给我就可以了，只发内容就行了，其他不用说了**"
> - "**用英文跟他联系**"（跟随上下文，不希望我啰嗦地解释）

**关键信号**：
1. 这不是某次任务的特殊要求——**整个会话（25+ 轮）持续重复**这一偏好
2. 任务类型包括：Maria 案邮件、巴基斯坦客户 GBM 邮件、GBM 付款方案邮件、PayPal 替代方案微信、微信群提醒模板、3 档服务重构邮件
3. **任何一个起稿任务**（不只是抖音/小红书），用户都希望**绝对最小化包装**

**触发器归纳**：
- "改好发我" / "写一段英文" / "发微信" / "帮我写一封" / "翻译成英文" 等**任何起稿任务** → 都进"复制用"模式
- 不只是"复制用"3 字触发，任何暗示"我要拿去用"的指令都触发

**改动方向**（已 patch 到 SKILL.md Step 3）：
- 起稿任务的输出格式强制为：
  ```
  [从这里开始复制 ↓]
  <正文>
  [复制到这里结束 ↑]
  ```
- 框外**只**允许：占位符提醒（如 `[name]`）、schema/敏感信息提醒
- 框外**禁止**：战略说明、"我做的关键事/没做的事"、emoji、CTA 钩子、"我做了/没做" 总结

**已知问题**：
- 这个规则**可能太严**：如果用户偶尔想要"详细解释 + 文案"，需要他显式说"这次加说明"才能破例
- 当前没有"用户想要详细解释"的反触发器——下次用户说"详细分析这封邮件"时记得**破例**

**触发器优先级**：
- 高优先级（永远遵守）：直接起稿任务（写邮件 / 微信 / 朋友圈文案 / 报告附言）
- 中优先级（默认遵守）：模板生成（wechat 模板 / 邮件模板 / 营销文案模板）
- 低优先级（**不**遵守）：用户主动问"为什么这么写 / 怎么改 / 给我详细分析"——这时需要详细解释
