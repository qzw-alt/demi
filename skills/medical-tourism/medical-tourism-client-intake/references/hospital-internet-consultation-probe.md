# 医院"互联网问诊"渠道核实（2026-07-08 北大第一 + 中日友好案）

触发场景：伟烨电话问了某家医院的"互联网问诊 / APP / 小程序"路径后，让我"去官网查一下是不是真的有"。**这一步是接诊流程评估的关键输入**——如果医院真有可用的患者端互联网问诊入口，海外患者就能绕开"必须本人到场"的硬规则做远程预审；如果只是名义上有但实际空壳，就得换打法。

---

## 1. 标准化诊断 4 步法

### Step 1 — 官网"互联网医院"入口识别

```bash
curl -sS -L -A "Mozilla/5.0" -o /tmp/hospital.html "https://www.<医院域名>/" --max-time 15
```

在 HTML 里 grep 关键词：

```bash
grep -oE "互联网|在线问诊|远程问诊|在线复诊|互联网医院|APP|app|移动应用|公众号|小程序|挂号|在线|智慧医院|掌上医院" /tmp/hospital.html | sort | uniq -c
```

抓到"互联网医院"链接后，**直接 GET 这个链接看是不是占位符**：

```bash
curl -sS -L -A "Mozilla/5.0" -o /tmp/ih.html "https://www.<医院域名>/<ih-page>.shtml"
cat /tmp/ih.html | head -100
```

### Step 2 — 占位符空壳识别（最关键的一步）

官网头部挂着"互联网医院"图标，但点开后可能是**4 年前的占位符页面**。识别信号：

| 信号 | 例子 |
|------|------|
| title | `网站建设中` |
| meta `页面生成时间` | `2022-09-19 18:02:48`（陈年页面） |
| meta `ColumnName` / `ColumnDescription` / `ColumnKeywords` | 都是 `建设栏目` |
| 页面 body | 只有 `<div class="main-box"></div>` 一个空 div |
| 文件大小 | 通常 < 1.5KB |

**对策**：不要因为官网有"互联网医院"图标就告诉伟烨"它能做"——**必须 GET 子页面验证**。

### Step 3 — iTunes Search API 查官方 APP

微信小程序 / 安卓市场没法直接 API 拉，但**iTunes Search API 是真实可达的 JSON 端点**：

```bash
curl -sS -A "Mozilla/5.0" \
  "https://itunes.apple.com/search?term=<医院中文名>&country=cn&entity=software&limit=10" \
  -o /tmp/itunes.json
```

返回 JSON 结构里：

- `trackName` —— APP 中文名
- `bundleId` —— 唯一包名（可直接判定真伪）
- `sellerName` —— **发行方**，**必须是医院官方名称**，否则是第三方
- `genres` —— 类型
- `trackViewUrl` —— App Store URL

**关键检查**：用 `sellerName` 字段筛官方 APP。中日友好案例里，`sellerName = "China-Japan Friendship Hospital"` 就是真的官方 APP；其他 `com.bjycc.mao` / `com.yht120.bjyhtgh` 等都是第三方挂号平台。

### Step 4 — Lookup API 拿 APP 详细描述

拿到 APP ID 后：

```bash
curl -sS -A "Mozilla/5.0" \
  "https://itunes.apple.com/lookup?id=<APP_ID>&country=cn&entity=software" \
  -o /tmp/lookup.json
```

返回 `description` 字段直接告诉你**这个 APP 到底有哪些功能**——"预约挂号 / 取报告单 / 健康宣教" vs "在线问诊 / 视频通话" 区别一目了然。

**重要提示**：中日友好医院的"医护端 APP"描述里写着"让医生与患者文字语音视频通话"，但 `bundleId` 后缀是 `.doctor`，**这是医生用的、患者装不上也没用**。**判断时不能只看描述，必须看 bundleId / 安装对象**。

## 2. 实测案例：中日友好医院 (2026-07-08)

### 调研结果

| 项 | 结果 |
|---|---|
| 官网头部 | ✅ 有「互联网医院」入口图标 |
| 入口子页 URL | `https://www.zryhyy.com.cn/zryh/c103319/wzjs.shtml` |
| 入口子页内容 | ❌ **占位符空壳** — title="网站建设中" / 生成时间=2022-09-19 / ColumnName="建设栏目" |
| 官方 iOS APP（患者端） | "中日医院" `com.bjhsyuntai.zhongri.patient` / seller="China-Japan Friendship Hospital" / 版本 1.5.7 (2026-05-25 更新) |
| 患者 APP 功能 | ❌ **只有预约挂号 + 取报告单 + 健康宣教，没有在线问诊** |
| 官方 iOS APP（医护端） | "中日友好医院医护" `com.bjhsyuntai.zhongri.doctor` |
| 医护 APP 功能 | ✅ 支持文字/语音/视频问诊，**但仅医生端，患者用不了** |

### 结论

**中日友好医院没有可用的患者端在线问诊入口**。电话里对方说"APP 上面有互联网问诊"，要么是**4 年前的功能承诺**（2022-09 的占位符页面就是当年雏形），要么是对方**把"医护端功能"误当成患者端**。

## 3. 实测案例：北大第一医院 (2026-07-08)

### 调研结果

| 项 | 结果 |
|---|---|
| 官网 `pkufh.com` | ❌ **2010 年代旧版网站**，只有医院介绍 + 引导页，**没有互联网医院入口、没有科室导航、没有挂号入口** |

| iOS 搜"北医一院" | 0 自有 APP，5 个第三方挂号 APP |
| iOS 搜"pkufh" | 0 结果 |

### 结论

**北大第一医院完全没有互联网医院 / 在线问诊入口**。必须本人到场 + 普通门诊挂号 + 一周后排号。

## 4. 给伟烨汇报的措辞模板

调研完后给伟烨的报告要**三段式**：

1. **先说有没有入口**（官网图标 / APP 在不在）
2. **再说是真的还是名义上**（占位符？APP 实际功能？）
3. **最后给伟烨一个选择**（绕开这家？走第三方平台？告诉患者本人到场？）

**反例**（不要这样写）：
> "中日友好医院有互联网医院入口，可以走 APP 在线问诊。"
>
> —— 这是错的，名义上有但实际空壳。

**正例**：
> "中日友好医院官网确实挂了'互联网医院'图标，但点开是 2022 年的占位符空壳页面；他们官方 APP「中日医院」只有预约挂号+取报告单，没有在线问诊。医护端 APP 有问诊功能但只给医生用。**没有可用的患者端在线问诊入口**。"

## 5. 这套方法论的覆盖范围

未来再遇到任何医院的"互联网问诊"调研，**4 步法直接复用**：

- 卫健委直属医院（北京协和、华西、湘雅、齐鲁等）
- 省级人民医院
- 大学附属医院
- 部队医院（301 等）
- 专科医院（阜外、安贞、积水潭等）

**通用约束**（基于 2026-07-08 实测推论）：

- 大陆三甲的互联网医院主用途是**复诊**，**首诊（含外籍患者）几乎都不允许线上完成**
- 跨境外籍患者要触发国家卫健委备案流程，**只有少数国际化三甲能跑**（如北京协和、上海华山）
- "提前把资料发给大夫私下审核"在三甲几乎不可能——**医生不能脱开医院受理外部会诊资料，是合规红线**
