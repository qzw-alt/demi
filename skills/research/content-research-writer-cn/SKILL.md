# Content Research: Chinese Medical News (医疗新闻热点研究)

Research Chinese medical/health news热点 for daily article publishing on chinahospitalsguide.com.

## Context

- Website: https://chinahospitalsguide.com (medical tourism guide for China)
- Article output: `news/` directory, file naming `YYYY-MM-DD.html`
- Publishing cadence: 1 article per day (栏目新建期)
- Quality bar: 去AI化评分 >60; no good热点 = no publish (宁缺毋滥)

## Research Sources

Prioritize these for Chinese medical/health news:

- **丁香园** (dxy.cn) — most authoritative Chinese medical professional portal
- **健康报** (jkj.cnjkw.com) — 人民健康网 (People's Health) — state medical newspaper
- **国家卫健委** (nhc.gov.cn) — official policy announcements
- **医学界** (yiduozhe.com) — medical news
- **澎湃新闻** (thepaper.cn) — general news with health section
- **财新** (caixin.com) — health policy coverage
- **PubMed/知网** — for cutting-edge clinical research
- **微博热搜** — trending health topics (weibo.com)
- **微信搜索** — 搜一搜 health articles

## Additional High-Value International Sources

For clinical advances with Chinese relevance (新疗法, 新药上市, 国际临床试验), also check:
- **ASCO** (asco.org) — oncology congresses, published June 2026 with CROWN trial 7-year data
- **ESMO**, **AHA**, **ACC** — major congresses with Chinese hospital co-authorship
- **NEJM**, **The Lancet**, **JAMA** — high-impact clinical papers with Chinese authors
- Congress press releases often have the best patient-facing summaries

**Pitfall**: High-quality international clinical data (e.g., ASCO abstract releases) can outrank Chinese domestic sources for clinical progress topics. Check congress websites directly when domestic sources are thin.

**Straits Times (verified 2026-06-22) — third-tier inbound medical tourism source, complements BT/Bloomberg:** when BT/Bloomberg has already shipped a similar "China medical tourism macro" piece (which is the case for the 2026-06-11 BT article on Stuart Lye, $65K cost, US$1.3B market), **www.straitstimes.com** is the next tier of source for follow-on coverage. **South China Morning Post (SCMP) — paywalled, but Mirage News mirrors most SCMP medical stories (verified 2026-06-29):** when Bing News returns a `scmp.com/news/...` URL for a Hong Kong medical story, the canonical SCMP page returns ~1MB of HTML but only the lead paragraph (gated body). Standard `<p>` extraction returns 7 short paragraphs totaling <500 chars. **Fix:** when the SCMP URL surfaces for a HKUMed / Chinese University of Hong Kong / Hong Kong hospital story, search Mirage News first (`curl -A "Mozilla/5.0 ..." **SCMP body extraction gotcha when paywall is bypassed (verified 2026-06-29):** even when an SCMP page is partially accessible (1MB fetched), the HTML body contains a CSS bundle dump of ~57260 chars inside `<style>` tags that gets pulled into any naive `<p>` extraction. The fix: strip styles before paragraph extraction with `re.sub(r'<style[^>]*>.*?</style>', ' ', c, flags=re.DOTALL)` then continue with the standard `<p>` regex. Without this strip, the "lead paragraph" looks like ~57KB of CSS, hiding the actual content. This is reusable as a `/tmp/extract_article.py` script.

**De-duplication check before shipping (verified 2026-06-12):** before writing a Bloomberg/BT-sourced article on a topic with prior chinahospitalsguide coverage, run `grep -lE "<key-entity-names>" news/*.html` to surface existing articles that may already cover the same anchor points. The 2026-06-12 cron run nearly duplicated the 2026-04-18 SinoUnited CAR-T article and the 2026-06-06 Pakistani CAR-T piece before the de-dup check; the BT article only justified a fresh publication because it carried genuinely new data points (clinical-trial-fee ban, brain-implant milestone, market projections, NZ patient narrative). The general rule: a "China medical tourism landscape" Bloomberg piece is shippable IF it has ≥3 data points absent from the prior chinahospitalsguide coverage; otherwise skip the day (宁缺毋滥).

**De-dup BEFORE source fetch, not just before writing (verified 2026-06-14):** the 2026-06-14 cron run wasted ~6 tool calls fetching SCMP, IBTimes, Scientific American, Bangkok Post, GlobalTimes, and the Lecheng PR Newswire piece for two fresh-research candidates (xenotransplant + Lecheng service center) before discovering both were already covered by 06-11 BT/Bloomberg and 06-03 Lecheng articles respectively. The corrected workflow:
1. Bing News search → get 5-10 candidate headlines
2. **`grep -lE "(key-noun-1|key-noun-2|key-data-point)" news/*.html` for EACH candidate headline's anchor strings** — if 1+ article matches, skip the source fetch and move to the next candidate
3. Only fetch the source for candidates with 0 matches

This front-loads the de-dup check to save source-fetch tool calls. The 2026-06-13 BT/Bloomberg record is `grep -lE "(Stuart Lye|65,000|clinical-research fees|brain-implant|Market Research Future|US\$1\.3B)" news/*.html` returning 0 matches; the 2026-06-14 candidates would have failed the same grep on `xenotransplant|pig liver|Guangxi Medical` (matched 06-11 article) and on `Lecheng Service Center|10,000 inbound|560 innovative` (matched 06-03 article), saving 5-6 tool calls.

**Cron iteration cap near-miss: state on disk is durable (verified 2026-06-14):** the 2026-06-14 cron run completed Steps 1-5 (research, article, humanize to 95, sitemap, index.html) and the local git commit (hash `c8bffec`) succeeded, but the cron iteration cap was hit before `git push origin master` and the `sleep 180 && curl HTTP 200 verify` could run. The article is fully baked and on the master branch locally, just not pushed. **The next cron run should detect this state with `git status` ("Your branch is ahead of 'origin/master' by N commits" with N≥1 and a 2026-06-14 article in the working tree) and JUST push + verify, NOT start fresh research.** The recovery command is documented in `references/pending-2026-06-14-akeso-gumokimab-shipped.md`. This is the first cron run where the cap was hit between commit and push — earlier 2026-06-XX runs hit the cap earlier (during research or writing) and used the pending-file handoff instead. The post-commit cap-hit is a NEW failure mode and a NEW recovery pattern.

**Cron iteration cap hit DURING research phase (verified 2026-06-16) — the THIRD failure mode:** the 2026-06-16 cron run burned ~15 tool calls on Bing News HTML format change (the recipe was now broken — see pitfall above), Yahoo Finance universal block, ChinaDaily section scraping, Akeso press archive, and Manila Times PR Newswire feed before the cap fired mid-research with no article written. **Sibling subagent warning during shared-file edits (verified 2026-06-14):** when patching `sitemap.xml` or `news/index.html`, the patch tool can emit: `_warning: <file> was modified by sibling subagent '<uuid>' but this agent never read it. Read the file before writing to avoid overwriting the sibling's changes.` This indicates parallel subagent or cron activity on the same shared file. The fix: immediately `read_file` the target after the warning to verify state. In the 2026-06-14 run, both warnings were spurious (no actual concurrent edit had been made) and the patches went through cleanly, but verifying with `head -20 file` + `grep new-entry file` is the safe move. If a sibling edit IS present, coordinate via `git status` + `git diff` before merging the changes.

**Misattribution gotcha when paraphrasing third-party news (NEW — verified 2026-06-30, Order 818):** when the canonical source is paraphrased or quoted in a third-party article (e.g. GEN paraphrasing an NMPA notice, pharmaphorum paraphrasing a press release, BT/Bloomberg paraphrasing a hospital announcement), it is **easy to garble the quote attribution** — the third-party article may attribute the quote to one person while the original press release attributes the same position to a different person (or to a corporate position), and copying the quote wholesale pulls in the wrong name. The 2026-06-30 run had this happen with a quote originally from a CHDF commentary attributed to a different person in the GEN paraphrasing. The fix was a global name swap before the article was committed. **Decision rule:** when writing an article from a third-party news source that paraphrases or quotes a primary source, **always verify the quote attribution against the original source BEFORE writing the body prose.** Verification cost is 1-2 extra tool calls (fetch the original press release, grep for the name + quote). Cost of getting it wrong is a publishable factual error. **Verification recipe:** (1) From the third-party article, extract 2-3 named quotes + their attributions. (2) For each named quote, search the canonical source URL (often referenced in the third-party article's first paragraph) for the same quote. (3) If the canonical source uses a different attribution, use the canonical attribution. (4) Build a per-source quote map (name → quote → verbatim text) BEFORE writing the article, not after.

**Practical research recipe** (saves the most time and budget):

1. **Bing News first** for headline discovery:
   `curl -A "Mozilla/5.0 ..." "https://www.bing.com/news/search?q=QUERY&qft=interval%3d%229%22" | grep -oE 'href="https?://[^"]+"'`
   The result includes URLs to the major outlets and the syndication mirrors.
2. **For any candidate URL, fetch the page and extract the publication date BEFORE writing.** The single most common wasted-hour pattern in cron runs is grabbing a story that looks fresh but is 6–12 months old. Date-extraction recipes per outlet:
   - `chinadaily.com.cn`: `grep -oE '<meta name="publishdate" content="[^"]+"'` — reliable
   - Most others: `grep -oE '<meta[^>]*property="article:published_time"[^>]*content="[^"]+"'`
   - Reject anything >30 days old for "fresh 热点" claims; older than 90 days is only OK for evergreen framing (e.g. "2025 figures" with no claim of news today).
3. **Direct press release for the drug/company in question** (e.g. `akesobio.com/en/media/akeso-news/`). These pages are usually publicly scrapeable.
4. **CrossRef for published papers** (when you have a DOI from CrossRef or PubMed): `curl "https://api.crossref.org/works/DOI" -o /tmp/x.json && python3 /tmp/parse.py`
5. **Skip dxy.cn / yiduozhe.com / thepaper.cn** unless you have a specific working bypass — they will waste 2–3 tool calls each.

**"Pivotal" / "landscape" banned-vocab fix for clinical research prose (verified 2026-06-23):** when writing articles about clinical trial results (registration trials, Phase 3 readouts, NMPA approvals), the humanize_score.py script flags "pivotal" (used to describe the trial that supports the approval) and "landscape" (used to describe the competitive field or treatment sequence). For the 2026-06-23 CarsGen satri-cel article, 5 hits of "pivotal" and 3 hits of "landscape" were the dominant score penalties at first pass (35/100), with em-dash density already at the 17-23/1200 baseline. Two clean swaps work in clinical-research prose:
- `pivotal` → `registration` (e.g. "the pivotal Phase 2 trial" → "the registration Phase 2 trial") — `registration trial` is the actual FDA/NMPA term for the trial that supports marketing approval, so this swap is both correct and the script's preferred phrasing
- `landscape` → `field` or `picture` (e.g. "the competitive landscape for solid-tumor CAR-T" → "the competitive field for solid-tumor CAR-T"; "broader CAR-T cost landscape" → "broader CAR-T cost picture") — both swaps are 1-word substitutions that preserve meaning

After these swaps, the 2026-06-23 article went from 35/100 → 90/100 in 7 small patches. **Re-confirmed 2026-06-26** on the UCB Tellier / China-drug-discovery article (2,394 words, 95/100 final) — the same 2-line fix (`landscape → picture`, `pivotal → registration` plus removing 1 × `actually`) took the score from 74 → 95 in 2 patches with no prose restructuring. The "pivotal → registration" / "landscape → picture" swap is now a verified repeatable pattern across 2 consecutive articles (06-23 + 06-26) and 2 article archetypes (regulatory approval + policy/pharma framing). **The general lesson:** when the score is in the 30-80/100 band on a clinical/regulatory/policy article and the only flagged banned-vocab words are `pivotal` and `landscape`, the fix is the 2-7 small swaps above. Do NOT restructure the prose.

**IND-clearance article structure (verified 2026-06-24, Mabwell 6MW5311 LILRB4×CD3 TCE story):** the existing 4-part structure (Phase X data readout) and 7-part structure (regulatory approval) cover the two most common article types on this site. IND clearance is a THIRD distinct article type that needs its own structure — the data is preclinical, there is no efficacy signal to anchor the angle, and the press release is dense with mechanism, indication, and competitive context that has to be unpacked. The verified 6-section structure for an IND-clearance article (used on the 06-24 Mabwell story, 3,115 words, 75/100) is:

1. **Lead** — what just happened (NMPA IND clearance), who announced it, what the molecule is, which indications, the "first-in-class" or "first-in-China" framing
2. **Why this story is shippable** (data-box callout) — the candidate's distinguishing feature, the indication's unmet need, the medical-tourism angle for international patients
3. **What the molecule does** — mechanism deep-dive: target biology, format choice (asymmetric 2+1, steric hindrance, masked CD3, etc.), why this is different from first-generation TCEs
4. **Preclinical data behind the IND** (bulleted) — in vitro cytotoxicity, in vivo tumor inhibition, NHP safety package (the standard IND-enabling trio)
5. **The three indications** (sub-headings H3 for each) — separate paragraphs for AML, CMML, MM with epidemiology, standard of care, and the gap the candidate is intended to fill
6. **Pipeline / competitive context** — how the candidate fits into the company's broader pipeline, who else is in the field, why LILRB4 (or whatever target) in 2026
7. **What to watch in the next 12-18 months** — first clinical readout timing, key endpoints (MTD, RP2D, CRS rate, ORR), competitive context for the readout
8. **Medical-tourism translation** — clear-eyed assessment of when (or if) the candidate might be available to international patients, with cross-links to the relevant 2026-XX articles in the same indication or related fields

The mechanism subsection (section 3) is the critical differentiator — without it, the article reads as a press-release paraphrase, and the humanize score drops into the 50-60 band. The competitive context (section 6) is the second differentiator — the reader who already knows the field will skim it, but the reader who doesn't will use it as the entry point for understanding why the candidate matters. The 06-24 Mabwell article ran ~3,115 words at 75/100 with this structure; the article would have been 2,200 words and 55/100 without the mechanism and competitive-context sections.

**"actually" in H2/H1/H3 headings is a single-point score kill (verified 2026-06-22, RECONFIRMED 2026-06-24, RECONFIRMED 2026-06-25):** the 2026-06-24 Mabwell article had a single `actually` hit in the H2 ("What 6MW5311 actually does") that dragged the score from 75 (would have been 80+) → 67 (the H2 hit alone caused an 8-point swing). The 2026-06-25 Unixell article had TWO `actually` H2 hits ("What UX-DA003 actually is" + "What UniXell actually announced") that dragged the score from 72 (would have been 80+) → 56 — a 16-point swing from 2 hits. Patching both H2s in one cycle each pushed the score back to 72/100. **Rule update (strengthens the 2026-06-22 rule):** when running the humanize score, ALWAYS grep for `actually` in heading tags (H1/H2/H3) separately from body prose. A single `actually` in a heading is worth 5-8 score points; two hits compound. The body-prose tolerance of 1-2 `actually` hits per 4,000 words is unchanged from the 2026-06-08 rule, but headings are strict.

**Banned-vocab hits inside source-quote attributions are FALSE POSITIVES (NEW pitfall — verified 2026-06-25):** when the humanize_score.py script flags `leverage`, `landscape`, `pivotal`, `navigate`, or `actually` inside a `<blockquote>`, `<div class="pullquote">`, or any other direct-quote container that is being attributed to a named source (a person, a company, a press release), LEAVE IT VERBATIM. The 06-25 Unixell article had one `leverage` hit inside a UniXell pullquote (`"We leverage a unified iPSC seed cell platform..."`) that was left untouched and shipped at 72/100. Rewriting the quote to "We use" would have changed the source's stated position from "exploit strategic advantage" to "apply mechanically" — a semantic change the source did not authorize. **Decision rule:** if removing the word changes the source's stated position, leave it; if the swap is purely lexical (e.g. actually → in fact in body prose), patch it. The score penalty is 1 point per false-positive hit but the journalistic value of verbatim source quotes outweighs the score optimization.

**`sleep N && curl` 60-second foreground timeout (NEW failure mode — verified 2026-06-25, RE-CONFIRMED 2026-06-29, RE-CONFIRMED 2026-06-30):** the standard post-push verify sequence `sleep 180 && curl -s -o /dev/null -w "HTTP %{http_code}\n" https://chinahospitalsguide.com/news/YYYY-MM-DD.html` can hit the terminal tool's 60-second foreground timeout, especially when chained in one call. The 06-25 run hit this twice, the 06-29 run hit it once, the 06-30 run hit it once — 4 documented instances across 3 different cron runs. The 06-30 instance was the cleanest: the first verify call returned `exit_code: 124, "Command timed out after 60s"` on the `sleep 180` portion, the curl never ran. **Fix:** ALWAYS add `--max-time 30` to the curl call, and split the sleep and curl into two calls if the cron budget allows. Working recipe:
```bash
# Call 1: sleep alone (will hit 60s, but cron can move on)
sleep 180
# Call 2: verify with bounded curl
curl --max-time 25 -s -o /dev/null -w "HTTP %{http_code}\n" URL
```
The 06-30 article was pushed successfully (commit `a9f3365`); the verify HTTP 200 came on the second attempt using `--max-time 25`. **Future-proofing:** when writing the verify sequence in a cron run, always assume the first attempt will time out and budget for 2 calls. Don't try to chain `sleep 180 && curl --max-time 30` in a single foreground call — the 60-second timeout will fire on the `sleep` portion, not on the curl, and the curl never runs.

**Cell-therapy Phase 1 article archetype (NEW structure — verified 2026-06-25):** the existing 4-part (Phase X data readout), 7-part (regulatory approval), and 6-section (IND clearance) structures all assume either efficacy data OR an approved drug label as the news anchor. **Cell-therapy Phase 1 announcements** (iPSC, CAR-T Phase 1 expansion, gene therapy Phase 1) are a FOURTH archetype because the data is preclinical-or-Phase-1 with no published ORR/PFS, the manufacturing platform IS the news (allogeneic vs autologous, iPSC bank quality, lineage tracing), the competitive landscape is mature and named (iPSC Parkinson's has 3-4 named competitors), and the access question is structural ("where do I enroll") not trial-specific ("what's the response rate"). **Verified 7-section structure** (used on the 06-25 Unixell story, 2,112 words, 72/100):

2. Why the structural claim is real, not just PR (data-box callout) — single iPSC cell bank, shared manufacturing, etc.
3. What the molecule actually IS — cell lineage, platform, mechanistic rationale, published cohort references
4. What was actually announced — what the clearance permits, what is NOT in the announcement, pipeline context
5. Competitive context — name 3-4 named programs, flag data the press release does NOT yet support
6. What to watch in the next 12-18 months — concrete data points, competitive readouts
7. Medical-tourism translation — bulleted patient questions + access-path assessment

Sections 2 (data-box) and 7 (medical-tourism translation with bulleted questions) are the differentiators — without them the article reads as a press-release paraphrase and the humanize score drops 15-20 points.

**Manila Times PR Newswire body extraction recipe (NEW technique — verified 2026-06-25):** the Manila Times page for a PR Newswire story is typically 300-360KB but the actual body text is buried inside a ~140KB JavaScript payload (the Manila Times site framework). Standard `<article>`, `<div class="article-body">`, `<div class="news-content">` regex patterns return 0 chars. **Working recipe:** grab the 4-5 substantive `<p>` tags with 200-5000 chars each (anything shorter is nav/sidebar; anything longer is the JS payload), supplemented by the full lead from `<meta property="og:description" content="...">`. Together these yield enough text for a 2,000-2,500 word article from a single Manila Times fetch. Fallback chain if og:description is empty: `<meta property="twitter:description">` → `<meta name="description">` → `<meta itemprop="...">` blocks → JavaScript string search for dateline + 5KB forward slice. If all fail: try `finanznachrichten.de` (verified 2026-06-18) or the company's IR page.

**Structural-policy article archetype (FIFTH archetype — verified 2026-06-30, China NHC Order 818 cell & gene therapy framework):** the existing 4 archetypes (Phase X data readout, regulatory approval, IND clearance, cell-therapy Phase 1) all assume the news is an **asset** (a drug, a cell therapy, a gene therapy) doing something. Structural-policy articles are different — the news is a **regulatory framework** that changes what assets (and hospitals, and patients) can do. Verified 7-section structure (used on the 06-30 Order 818 article, 4,422 words, 69/100): (1) Lead — what just happened, who issued it, what it covers, "exists nowhere else" framing. (2) Why this story is shippable (data-box callout) — eligibility count, capacity gap, medical-tourism angle. (3) What the order actually does — bulleted or sub-headed by clause: eligible product classes, hospital eligibility, chargeable-cost framework, post-trial data submission. (4) What changed from the prior framework — table or side-by-side comparison. (5) Who benefits — three stakeholders (hospitals, patients, NMPA pipeline). (6) What to watch in the next 12-18 months. (7) Medical-tourism translation — bulleted patient questions + access-path assessment. **Differentiators that lift the score:** sections 2 (data-box callout) and 4 (prior-vs-new comparison) are load-bearing — without them the article reads as a notice paraphrase and the humanize score drops into the 50-60 band. Em-dash density 17.6/1200 is in baseline; long-article 60-70 ceiling applies (4,422 words → 69/100 is the realistic target, don't waste tool calls trying to push higher).

**IR-page domain collision (NEW pitfall — verified 2026-06-25):** small Chinese biotechs' `companyname.com` domains are often NOT the company's website — they can be Chinese template-generated wanhu sites (look for `<meta name="design" content="万户网络 www.wanhu.com.cn">` or `<meta name="Author" content="万户网络">` in the head). The biotech's actual English web presence is typically PR Newswire syndication only (manilatimes.net / finanznachrichten.de mirror). Don't waste 2-3 tool calls trying to extract press releases from a wanhu-template site — go directly to the PR Newswire mirror.

**Two-source abstract extraction for peer-reviewed papers (NEW technique — verified 2026-06-28, Tangdu Hospital PEEK stent paper):** when the canonical source for an article is a peer-reviewed paper in a journal that the cron sandbox can't fetch directly (Frontiers, ScienceDirect, Wiley, Springer paywalls / Cloudflare), the standard pattern is **CrossRef API first, then direct journal HTML fetch as a fallback**:

1. `curl -A "Mozilla/5.0 ..." https://api.crossref.org/works/DOI` (e.g. `10.3389/fbioe.2020.00732`) — returns DOI metadata as JSON. **Caveat:** the CrossRef JSON often returns `abstract: null` or `abstract: ""` for many papers, even when the paper is open access. The `title`, `author`, `container-title`, and `subject` fields are reliably populated, but the `abstract` field is not. The 06-28 run got title/authors/journal/DOI clean but abstract was empty.
2. **Fallback: direct fetch the journal's HTML page for the same DOI.** Frontiers is open access and serves the full paper HTML directly: `curl -A "Mozilla/5.0 ..." https://www.frontiersin.org/journals/bioengineering-and-biotechnology/articles/10.3389/fbioe.2020.00732/full` returns ~735KB of HTML with the abstract inside `<meta name="description" content="...">` (verified 2026-06-28 with He Dali et al. 2020 nutcracker stent paper). ScienceDirect / Wiley / Springer typically fail with Cloudflare challenges, so this fallback only works for open-access journals. Confirmed working journals for the fallback pattern: Frontiers, MDPI, PLOS, BioMed Central (BMC), some Hindawi titles. Pattern for extracting the abstract: `grep -oE 'name="description" content="[^"]+"' frontiersin.html | head -1` returns the full abstract in the meta description tag.

**When to skip step 2 (and accept title-only from CrossRef):** if the journal is paywalled (NEJM, Lancet, JAMA, Nature, Science, most Wiley/Springer titles) and direct HTML fetch returns a Cloudflare challenge page (the 06-22 run hit this on Wiley Online Library), the CrossRef title + author + container-title metadata is enough to write a 1,500-2,500 word article if you already have other in-hand sources (e.g. company IR pages, press releases, case reports). The abstract is useful for verbatim quotes and data points, but for clinical-research articles where the press release / case report already provides the headline data (technical success rate, patient count, follow-up window), the CrossRef metadata alone is sufficient.

**Tool-call budget for this pattern:** 2 calls for the two-step (CrossRef + Frontiers HTML), 1 call for a one-shot `/tmp/check_dash.py` style script to extract the abstract from the HTML. Total 3 calls for a fully-verified clinical-paper source. Compare to the 4-6 calls previously burned on direct journal fetches that Cloudflare-blocked.
